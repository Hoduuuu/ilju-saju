# 일주 사주 사이트: 설계와 구현 계획

## Context
- 빈 폴더 `/Users/ptk_a240252/test_v.1`에서 새로 만드는 **내 컴퓨터 전용 사주 웹사이트**.
- 목표는 두 가지.
  1. 만세력 라이브러리로 **정확하게 계산**한 사주를 `claude -p`(구독 로그인)가 풀이한다.
  2. **일주별 일러스트와 색감**만 봐도 설명을 읽기 전에 분위기가 전달된다.
- 회원가입, 결제, 궁합, 기록 저장은 없음. 해외 출생은 이번 범위에서 제외.
- 환경: Node v26.8.2, npm 11.19.1, claude 2.1.270, git 설치됨. 폴더는 아직 git 저장소가 아님.

## 대비 보장 방식 (흰색 텍스트 가독성)
1. **팔레트 설계**
   - 일주 팔레트 = 일간 오행 색상(hue) × 일지 계절(명도·채도).
   - 텍스트가 놓이는 **상단 영역 색은 흰색 대비 4.5:1 이상인 짙은 톤**만 사용.
   - 파스텔 밝은 톤은 일러스트가 있는 하단 그라데이션 끝에만 사용.
   - 밝아지기 쉬운 오행은 이렇게 잡음.
     - 土: 황토 대신 짙은 오커·브라운
     - 金: 은색 대신 짙은 슬레이트
     - 火: 밝은 주황 대신 깊은 레드·버건디
2. **자동 테스트:** 60개 팔레트 전부 상단 텍스트 영역 색과 흰색(#FFF)의 대비비를 계산해 4.5:1 미만이면 실패(`tests/palette-contrast.test.ts`).
3. **실제 이미지 대응**
   - 이미지 프롬프트에 "상단 40%는 비워둔 단색 하늘/배경, 주인공은 하단"을 고정.
   - 텍스트 영역 뒤에 팔레트 상단색 → 투명으로 떨어지는 **스크림(반투명 그라데이션 덮개)** 을 항상 깔아 이미지가 밝아도 대비를 유지.
4. **이미지 검사 스크립트:** 생성된 PNG의 상단 텍스트 영역 평균·최대 밝기를 `sharp`로 측정해 스크림 적용 후에도 4.5:1 미만인 이미지를 목록으로 출력 → 재생성 대상.
5. **보조 요소:** 해시태그 칩은 반투명 짙은 배경 + 흰 글씨. 이 조합도 대비 4.5:1 이상으로 맞춤.

## 화면 구성
1. **입력 `/`**
   - 폼 필드.
   - 시간 입력 여부 비교 안내 카드.
   - "사주 보기" 버튼.
   - 입력값은 sessionStorage에만 두고 URL에는 넣지 않음.
2. **결과 `/result`** (사용자 시안 1번 구조)
   - **히어로 카드** (화면 높이 약 70%)
     - 일주 그라데이션 배경과 일러스트.
     - 해시태그 칩(정적 키워드).
     - 크고 굵은 흰색 한자 일주, 상징 문구.
     - AI 한 줄 요약(스트리밍으로 채워짐).
   - **히어로 위로 겹치는 흰색 바텀시트** (그랩바 포함)
     - 헤더: 왼쪽에 `甲子일주의 사주`, 오른쪽에 `다시 입력` 버튼(상태 초기화 후 `/`로 이동).
     - 원국 4칸(일주 강조, 시간 모름이면 시주 자리는 "?").
     - 오행 밸런스 바.
     - 대운 가로 스크롤(현재 대운 강조). 2026 세운 카드.
     - 절기 경계 경고(해당하는 경우만).
     - 풀이 섹션 카드 01~07(+notime).
     - 다운로드 버튼 2개(풀이 완료 후 활성화).
3. **도감 `/ilju`**
   - 오행 필터 탭(전체 / 木 / 火 / 土 / 金 / 水).
   - 2열 그리드. 카드는 히어로와 같은 세로 3:4 사각형(`IljuVisual` 소형): 그라데이션 배경 + 일러스트 + 흰색 한자 + 상징 문구.
   - 내 일주 카드에 "나" 배지.
4. **상세 `/ilju/[id]`**
   - 히어로와 같은 3:4 `IljuVisual`(한자·한글명, 상징 문구, 키워드) 아래에 정보.
   - 짧은 설명 2~3문장.
   - 계절 / 오행 / 음양 정보 행.

## 핵심 로직
- **`SajuResult`**
  - pillars(hour는 null 가능), elements, tenGods, hiddenStems, twelveStages, daeun[], currentDaeunIndex, seun2026, ilju id, warnings[].
  - 화면과 AI가 **같은 객체**를 사용.
- **`runClaude`** 인자 (구현 시 `claude --help`로 재확인):
  - `-p --output-format stream-json --verbose --include-partial-messages`
  - `--system-prompt-file`, `--model ${CLAUDE_MODEL ?? 'sonnet'}`, `--max-turns 1`
  - 도구 비활성화.
  - `shell: false`로 실행하고 프롬프트는 stdin으로 전달.
- **오류 처리**
  - `claude` 미설치나 로그인 안 됨 → 안내 문구 + 다시 시도.
  - 사용량 한도 → 안내 문구(계산 결과는 유지).
  - 120초 초과 → 중단하고 받은 부분까지 유지.
  - 요청이 끊기면 자식 프로세스 kill.
- **풀이 캐시:** 완성된 풀이는 sessionStorage에 저장해서 새로고침해도 재호출하지 않음. "다시 입력" 시 삭제.
- **이미지 스크립트**
  - `.env`의 `CF_ACCOUNT_ID`, `CF_API_TOKEN`을 읽음.
  - FormData로 prompt(상단 40% 빈 배경 고정 문구 포함), 768×1024, seed, 참조 이미지를 보냄.
  - 생성 후 `scripts/check-ilju-contrast.mjs`로 텍스트 영역 대비 검사.
  - 응답의 base64를 첫 바이트로 PNG/JPEG 판별 후 저장.
  - 이미 있는 파일은 건너뜀.

## 구현 순서
0. **착수 준비:** `git init`, 이 설계를 `docs/superpowers/specs/2026-09-14-saju-site-design.md`에 저장하고 커밋. writing-plans로 세부 작업 계획 작성.
1. **스캐폴드:** Next.js, Tailwind, vitest, Pretendard. 디자인 토큰, TabBar.
2. **계산 엔진 (TDD):** KASI 기반 정답 케이스를 먼저 작성한 뒤 구현.
   - 정답 케이스: 1997·2028 설날, 1987~88 서머타임, 입춘 경계, 야자시 경계, 윤달.
   - manseryeok가 정답과 다르면 보정표로 덮어씀.
3. **60일주 데이터와 도감·상세 페이지.** 더미 이미지로 먼저 완성.
4. **입력 페이지와 결과 페이지** (AI 없이 계산 결과만).
5. **`claude -p` 연동:** 섹션 파서 테스트(녹화한 가짜 스트림) → API route → 카드 스트리밍.
6. **PNG 다운로드 두 종류.**
7. **이미지 생성 스크립트:** 사용자가 토큰 입력 → 샘플 1장 확인 → 60장 생성 → 불량만 재생성.

## 검증
- `npx vitest run`: 정답 테스트, 대응표, 입력 검사, 섹션 파서, runClaude 오류 매핑(가짜 claude 실행 파일), **60개 팔레트 흰색 대비 4.5:1 검사**.
- 브라우저 확인 시 히어로·도감 카드의 흰색 텍스트를 실제 계산값(axe 등 접근성 검사)으로 확인. 이미지 적용 후 `check-ilju-contrast` 통과 확인.
- `npm run dev` 후 Browser pane 모바일 뷰포트(375×812)로 확인.
  - 3명 입력(시간 있음 / 모름 / 야자시 경계).
  - 히어로 색·이미지 변화, 실제 스트리밍 풀이, "다시 입력" 초기화.
  - 도감 필터와 상세, 내 일주 배지.
  - PNG 두 종류 다운로드 결과 확인.
- 계산 결과 몇 건을 한국 만세력 사이트 결과와 수동 대조.
- 이미지 스크립트: `--sample`로 1장 생성해 형식과 응답 구조 확인 후 전체 실행.
